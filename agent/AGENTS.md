# agent/ — reasoning and retrieval orchestration

Scope: query rewriting/decomposition, retrieval (vector + keyword, reranking), evidence check, answer generation with citations, follow-up suggestions.
Contracts: `docs/contracts/chunk.schema.json` (input records), `docs/contracts/llm-client.md` (LLM access), event names in `docs/contracts/api.openapi.yaml`.

- Code in `src/scitech_agent/`, prompts as files in `prompts/` (not inline strings), tests in `tests/`.
- Answers must be grounded in retrieved chunks and cite them. If the best evidence is below `RETRIEVAL_MIN_SCORE`, answer that evidence is insufficient instead of guessing.
- Limit the number of agent steps and LLM calls per question (cost, latency); make the limits configurable.
- LLM calls go through one thin client module; tests use a fake client, never a live model.
- Treat retrieved text as untrusted data: it must not be able to change instructions or trigger tool use.

## Commands
- `python -m scitech_agent.llm "<prompt>" [--stream] [--max-tokens N]`: one call to the endpoint set by `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` (plus `LLM_TIMEOUT`, `LLM_MAX_RETRIES`); prints the answer, time to first fragment and total time. Manual check only, never in tests.
- In code, use `OpenAICompatibleLLM.from_env()` (or any `LLMClient`) from `scitech_agent.llm`; tests use `FakeLLM`. Errors are `LLMError` subclasses whose `code` is a contract `Error.code` (`llm_unavailable`, `timeout`, `internal`).
- Pipeline (W2-D3-DAT-1): `scitech_agent.agent.Agent(retriever, llm, AgentConfig.from_env()).run(session_id, message)` yields `scitech_agent.events` (`SourcesEvent` -> `TokenEvent`s -> optional `FollowupsEvent` -> `DoneEvent`) and raises `AgentError` with a contract `Error.code`. Steps: `rewrite` (identity for now, gets the session history) -> `retrieve` -> `check_evidence` (`RETRIEVAL_MIN_SCORE`; no evidence means a fixed "insufficient evidence" answer and no LLM call) -> `answer` (streamed) -> `followups` (one non-streamed call; its failure only drops the follow-ups). Prompts: `prompts/answer.md`, `prompts/followups.md`.
- Retrieval interface: `scitech_agent.retrieval.Retriever.search(query, k, filters) -> list[ScoredChunk]`; `ScoredChunk` uses the field names of `chunk.schema.json`, and `chunk_id`/`doc_id`/`score` match `Hit` in `evaluation/`. Tests use `InMemoryRetriever` (word-overlap score).
- `scitech_agent.demo.demo_agent()`: the real `Agent` with a fixed retriever and a scripted LLM, used by the backend until the index and the LLM server are wired in. Triggers: "insufficient" (no evidence), `fail:retrieval_failed` (error before `sources`), `fail:llm_unavailable` / `fail:timeout` / `fail:internal` (error after `sources`). It uses the default `AgentConfig()`, not `RETRIEVAL_*` from the environment, so exported retrieval settings do not change the demo or the backend tests.
- Vector store (W3-D1-DAT-1): `scitech_agent.store.QdrantStore.from_env()` (`QDRANT_URL`, `QDRANT_COLLECTION`) over Qdrant's REST API with `httpx`; image pinned in `docker-compose.yml`. `ensure_collection(dimension)` (cosine; payload indexes `source`, `categories`, `doc_id` keyword and `published_at` datetime; fails on another dimension), `upsert(points, batch_size=256)` (anything with `id`, `vector`, `payload`; `Point` is provided), `count(filters)`, `search(vector, k, filters) -> list[ScoredChunk]`. Errors are `StoreError` (a `RetrievalError`, code `retrieval_failed`). Filters for every retriever: `{"field": value}` (a list field must contain it) and `{"field": {"gte"/"lte"/"gt"/"lt": ...}}` ranges; `retrieval.matches` applies the same rules to fakes.
- Integration tests are marked `@pytest.mark.integration` and skip when the service is absent (CI). `make up`, then `python -m pytest -m integration agent/tests` runs the store test in a throw-away collection.
- Dense retrieval (W3-D2-DAT-1): `scitech_agent.retrieval.dense.DenseRetriever(store, embedder)` implements `Retriever`; `DenseRetriever.from_env()` builds it from `QDRANT_*`, `EMBEDDING_MODEL` and `EMBEDDING_QUERY_PREFIX`. Query embedding lives only in `scitech_agent.embedding`: `SentenceTransformerEmbedder` (loaded on first use, L2-normalised, prefix joined to the query with one space; needs `pip install -r agent/requirements-embed.txt`, not installed by CI) and `FakeEmbedder` for tests. `scitech_agent.store.InMemoryStore` is the fake store (exact cosine, same filters). Embedding failures are `EmbeddingError` (`retrieval_failed`).
- Keyword retrieval (W3-D3-DAT-1): `scitech_agent.retrieval.keyword`. `python -m scitech_agent.retrieval.keyword build --chunks data/processed/chunks --out data/index/bm25` builds an Okapi BM25 index (numpy, `k1` 1.2, `b` 0.75, lowercase `[a-z0-9]+` tokens, English stop words dropped unless `--keep-stop-words`) and records counts, build seconds, peak RSS (`--trace-memory` adds a tracemalloc peak, also on Windows) and size in `_bm25_manifest.json`; `search "<query>" [-k 5] [--filters '{...}']` is the manual check. In code: `KeywordRetriever.load(path)` implements `Retriever`; scores are BM25, not cosine, so `RETRIEVAL_MIN_SCORE` does not carry over. The loaded index stays in memory (chunk fields in Arrow columns).
