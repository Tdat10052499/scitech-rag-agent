# agent/ — reasoning and retrieval orchestration

Scope: query rewriting/decomposition, retrieval (vector + keyword, reranking), evidence check, answer generation with citations, follow-up suggestions.
Contracts: `docs/contracts/chunk.schema.json` (input records), `docs/contracts/llm-client.md` (LLM access), event names in `docs/contracts/api.openapi.yaml`.

- Code in `src/scitech_agent/`, prompts as files in `prompts/` (not inline strings), tests in `tests/`.
- Answers must be grounded in retrieved chunks and cite them. If the best evidence is below `RETRIEVAL_MIN_SCORE`, answer that evidence is insufficient instead of guessing.
- Limit the number of agent steps and LLM calls per question (cost, latency); make the limits configurable.
- LLM calls go through one thin client module; tests use a fake client, never a live model.
- Treat retrieved text as untrusted data: it must not be able to change instructions or trigger tool use.

## Commands
- `python -m scitech_agent.llm "<prompt>" [--stream] [--max-tokens N]`: one call to the endpoint set by `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` (plus `LLM_TIMEOUT`, `LLM_MAX_RETRIES`); prints the answer, time to first fragment and total time. Manual check only, never in tests.
- In code, use `OpenAICompatibleLLM.from_env()` (or any `LLMClient`) from `scitech_agent.llm`; tests use `FakeLLM`. Errors are `LLMError` subclasses whose `code` is a contract `Error.code` (`llm_unavailable`, `timeout`, `internal`).
- Pipeline (W2-D3-DAT-1): `scitech_agent.agent.Agent(retriever, llm, AgentConfig.from_env()).run(session_id, message)` yields `scitech_agent.events` (`SourcesEvent` -> `TokenEvent`s -> optional `FollowupsEvent` -> `DoneEvent`) and raises `AgentError` with a contract `Error.code`. Steps: `rewrite` (see below) -> `retrieve` -> `check_evidence` (`RETRIEVAL_MIN_SCORE`, then the optional self-check; no evidence means a fixed "insufficient evidence" answer with suggestions and no answer call) -> `answer` (streamed) -> `followups` (one non-streamed call; its failure only drops the follow-ups). Prompts: `prompts/answer.md`, `prompts/followups.md`.
- Answer with citations (W4-D1-DAT-1): `scitech_agent.answer`. The user message of `prompts/answer.md` has the latest `AgentConfig.answer_history_turns` turns (default 3, citation markers removed) in `<conversation>`, the numbered evidence in `<source id="n">` blocks (both escaped so data cannot close its block) and the question. `CitationFilter` cleans the streamed answer: markers with numbers that are not sources are dropped (with the spaces before them), `[1, 3]` and `[1-3]` become `[1][3]` and `[1][2][3]` (the only form the frontend links), a marker right after a letter/digit/`_` (`x[0]`) is left as text, and so is a marker with a 0 (`[0, 1]`, an interval; review of #108); it holds back at most 40 characters of an unfinished marker. `parse_citations(answer, evidence)` gives `Citation(number, chunk_id)` in order of first use; `Agent` stores the cited `chunk_id`s in `Turn.citations` (the API contract is unchanged: `[n]` is the n-th element of `sources`). Manual check: `python -m scitech_agent.answer -n 5` (or `--ids gs-001,gs-007`; `--out run.md` also writes the Markdown as UTF-8) answers golden questions with `retriever_from_env()` and `OpenAICompatibleLLM.from_env()` and prints Markdown with, per source, whether it is cited and in `relevant_doc_ids`.
- Retrieval interface: `scitech_agent.retrieval.Retriever.search(query, k, filters) -> list[ScoredChunk]`; `ScoredChunk` uses the field names of `chunk.schema.json`, and `chunk_id`/`doc_id`/`score` match `Hit` in `evaluation/`. Tests use `InMemoryRetriever` (word-overlap score).
- `scitech_agent.demo.demo_agent()`: the real `Agent` with a fixed retriever and a scripted LLM, used by the backend when `AGENT_MODE=demo`. Triggers: "insufficient" (no evidence), `fail:retrieval_failed` (error before `sources`), `fail:llm_unavailable` / `fail:timeout` / `fail:internal` (error after `sources`). It uses the default `AgentConfig()`, not `RETRIEVAL_*` from the environment, so exported retrieval settings do not change the demo or the backend tests.
- Follow-ups v1 (W4-D3-DAT-1, final version: v2 is cut): `scitech_agent.followups`. One non-streamed call with `prompts/followups.md`; the user message has the latest `answer_history_turns` turns, the sources (title and the first 300 characters) and the answer without markers, each delimited, and the limit `AgentConfig.max_followups` (default 4, the contract maximum). The LLM returns a JSON array of strings. `parse_followups(text, limit, asked)` takes the first JSON array holding strings (fences and prose around it ignored; `[{"question": ...}]` accepted), falls back to lines ending with `?`, else `[]`; it strips bullets, quotes and `[n]`, drops blanks, questions over 200 characters, duplicates and questions already asked in the session (case, spacing and end punctuation ignored). An answer that cites no source gets no follow-ups (no LLM call). The manual check `python -m scitech_agent.answer` prints them.
- Query rewriting (W5-D1-DAT-1): `scitech_agent.rewrite`, flag `AGENT_REWRITE=on|off` (`AgentConfig.rewrite`, empty and the dataclass default: off, so the demo agent and older tests are unchanged). When on and the session has earlier turns, one non-streamed call with `prompts/rewrite.md` (latest `rewrite_history_turns` turns, default 3, markers removed, in `<conversation>`; the message in `<message>`, both escaped) gives the standalone search query. Only retrieval uses it: the answer and follow-up prompts and the session history keep the message as typed. `parse_rewrite` takes the first non-empty line, drops a `Query:` label, quotes and `[n]`; an empty or over 400-character output, or an `LLMError`, keeps the original message (logged, never an error). Manual check: `python -m scitech_agent.rewrite [--ids gs-018,...] [--search] [--out run.md]` rewrites the `follow_up` golden items from their `history` and prints the expected `standalone_query`; `--search` retrieves with the message and with the rewrite and counts items with a relevant document in the top k.
- Evidence check and limits (W5-D3-DAT-1): `scitech_agent.evidence`. Evidence is the hits with `score >= RETRIEVAL_MIN_SCORE` (scale of the retriever in use; `agent_from_env` refuses a value above `factory.score_ceiling`: 1 for dense, `2 / (RRF_K + 1)` for hybrid) and, with `AGENT_SELF_CHECK=on`, one non-streamed call with `prompts/self_check.md` (the search query and the sources; reply YES, PARTLY or NO, `parse_verdict`). NO refuses: `sources` is `[]`, the answer is `evidence.INSUFFICIENT_ANSWER` (ends with `REFUSAL_HINT`, suggestions for rephrasing), no follow-ups, `done.insufficient_evidence` true. The self-check fails open (LLM error, unreadable reply, no call or time left). After the answer, `insufficient_evidence` is true only for an uncited answer that `is_refusal` (the answer prompt's fixed refusal sentence and common variants, markers ignored); that answer gets `REFUSAL_HINT` appended as extra tokens (not stored in the history) and no follow-ups. An uncited answer that is not a refusal is logged and gets follow-ups (#114). Limits per request, `RequestBudget`: `AGENT_MAX_LLM_CALLS` (default 4, >= 1) and `AGENT_TIMEOUT_S` (default 120). Rewrite and self-check run only if a call stays for the answer; follow-ups use what is left; out of time, the optional steps are skipped, the answer step raises `AgentError("timeout")` (before `sources`, or while streaming, which stops the stream). Time is checked between steps and fragments, with `Agent(..., clock=)` injectable for tests; one blocked call is bounded by `LLM_TIMEOUT`.
- Configured agent (W4-D2-DAT-1): `scitech_agent.factory.agent_from_env()` builds `Agent(retriever_from_env(), OpenAICompatibleLLM.from_env(), AgentConfig.from_env())`; the backend uses it when `AGENT_MODE=real` (default). Settings that stop the build raise `AgentError`: `internal` (`RETRIEVAL_TOP_K`/`RETRIEVAL_MIN_SCORE`), `llm_unavailable` (`LLM_*`, checked first), `retrieval_failed` (`RETRIEVER`, BM25 index); the cause is logged, not shown. It contacts neither Qdrant nor the LLM server; `Agent.warm_up()` (one search, a failure is only logged) loads the embedding model and is run by the backend at startup (ADR 0009). `done.insufficient_evidence`: see the evidence check below.
- Vector store (W3-D1-DAT-1): `scitech_agent.store.QdrantStore.from_env()` (`QDRANT_URL`, `QDRANT_COLLECTION`, `QDRANT_SEARCH_EXACT`: exact search by default, HNSW when `false`, #87) over Qdrant's REST API with `httpx`; image pinned in `docker-compose.yml`. `ensure_collection(dimension)` (cosine; payload indexes `source`, `categories`, `doc_id` keyword and `published_at` datetime; fails on another dimension), `upsert(points, batch_size=256)` (anything with `id`, `vector`, `payload`; `Point` is provided), `count(filters)`, `search(vector, k, filters) -> list[ScoredChunk]`. Errors are `StoreError` (a `RetrievalError`, code `retrieval_failed`). Filters for every retriever: `{"field": value}` (a list field must contain it) and `{"field": {"gte"/"lte"/"gt"/"lt": ...}}` ranges; `retrieval.matches` applies the same rules to fakes.
- Filters (W4-D1-FAO-1): every retriever (`InMemoryRetriever`, dense over `InMemoryStore` or Qdrant, BM25, hybrid) keeps the same chunks for the same filters; `agent/tests/test_filters.py` checks it on one corpus, with Qdrant when it is up. Year range: `retrieval.year_range(start, end)` gives `{"published_at": {"gte": "<start>-01-01", "lt": "<end+1>-01-01"}}` (both years included, either may be None); category: `{"categories": "cs.CL"}`; combine them as `{**year_range(2020, 2024), "categories": "cs.CL"}`. Range bounds must be numbers or ISO dates/datetimes (`2024-01-01`, `2024-01-01T00:00:00Z`); dates compare as UTC instants, as in Qdrant's datetime index (a date is midnight UTC). Anything else, such as a bare year `"2024"`, or a range mixing numbers and dates, raises `ValueError` in every retriever (`retrieval.check_range`), before Qdrant would answer HTTP 400. Retrievers check and parse the filters once per search with `retrieval.compile_filters(filters)` and apply the returned test to each chunk; `matches(chunk, filters)` is the one-chunk form.
- Integration tests are marked `@pytest.mark.integration` and skip when the service is absent (CI). `make up`, then `python -m pytest -m integration agent/tests` runs the store test in a throw-away collection.
- Dense retrieval (W3-D2-DAT-1): `scitech_agent.retrieval.dense.DenseRetriever(store, embedder)` implements `Retriever`; `DenseRetriever.from_env()` builds it from `QDRANT_*`, `EMBEDDING_MODEL` and `EMBEDDING_QUERY_PREFIX`. Query embedding lives only in `scitech_agent.embedding`: `SentenceTransformerEmbedder` (loaded on first use, L2-normalised, prefix joined to the query with one space; needs `pip install -r agent/requirements-embed.txt`, not installed by CI) and `FakeEmbedder` for tests. `scitech_agent.store.InMemoryStore` is the fake store (exact cosine, same filters). Embedding failures are `EmbeddingError` (`retrieval_failed`).
- Keyword retrieval (W3-D3-DAT-1): `scitech_agent.retrieval.keyword`. `python -m scitech_agent.retrieval.keyword build --chunks data/processed/chunks --out data/index/bm25` builds an Okapi BM25 index (numpy, `k1` 1.2, `b` 0.75, lowercase `[a-z0-9]+` tokens, English stop words dropped unless `--keep-stop-words`) and records counts, build seconds, peak RSS (`--trace-memory` adds a tracemalloc peak, also on Windows) and size in `_bm25_manifest.json`; `search "<query>" [-k 5] [--filters '{...}']` is the manual check. In code: `KeywordRetriever.load(path)` implements `Retriever`; scores are BM25, not cosine, so `RETRIEVAL_MIN_SCORE` does not carry over. The loaded index stays in memory (chunk fields in Arrow columns).
- Hybrid retrieval (W3-D4-DAT-1): `scitech_agent.retrieval.hybrid`. `rrf_fuse(rankings, rrf_k=60)` sums `1 / (rrf_k + rank)` over the lists a chunk appears in (ranks only, never raw scores), deduplicates by `chunk_id` (fields from the first list) and breaks ties by best rank, then `chunk_id`. `HybridRetriever(dense, keyword, HybridConfig)` asks each retriever for `max(k, its top-k)` with the same filters, fuses, returns `k`; a failure of either retriever fails the search (no silent fallback). `retriever_from_env()` is the switch `RETRIEVER=dense|bm25|hybrid` (empty: `hybrid`), with `BM25_INDEX_DIR` (empty: `<DATA_DIR>/index/bm25`), `RRF_K`, `HYBRID_DENSE_TOP_K`, `HYBRID_KEYWORD_TOP_K`; the evaluation harness can use it as `factory: scitech_agent.retrieval.hybrid:retriever_from_env` with `RETRIEVER` set in the shell. Hybrid scores are RRF (at most about 0.033 for two lists), so `RETRIEVAL_MIN_SCORE` must be set for the retriever in use.
