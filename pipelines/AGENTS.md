# pipelines/ — data ingestion

Scope: download open datasets, clean them, split into chunks, create embeddings, load them into the vector store.
Source of truth for output: `docs/contracts/chunk.schema.json`. Sources and licences: `docs/03-data-sources.md`.

- Code in `src/scitech_pipelines/`, tests in `tests/`. Runtime dependencies in `requirements.txt` (create it with your first dependency).
- Every step must be re-runnable (idempotent) and take paths/URLs from arguments or env vars, not constants.
- Raw and processed data go to the git-ignored `data/` directory, never into git.
- Respect source terms and rate limits (e.g. pause between API requests). Record licence per record in the `license` field.
- Large-scale processing (Spark or similar) is justified only if the data volume requires it; record that decision in `docs/decisions/`.
- Validate outputs against the chunk schema in tests.

## Commands
- `python -m scitech_pipelines download --source arxiv|wikipedia|all [--out data/raw]`: raw data into `data/raw/<source>/` with a `manifest.json` (sizes, SHA-256). Re-running skips a complete source; `--force` downloads again. arXiv needs a Kaggle login (`kaggle auth login`); Wikipedia options: `--wiki-depth` (default 2), `--wiki-pause` (default 1 s), `--wiki-max-pages` (for a quick test). The arXiv manifest records the Kaggle dataset `version` (ADR 0003; W6 names the frozen index after it); the Wikipedia manifest records page counts per category depth, and pages without text are listed in `pages_without_text.txt` so a resumed run skips them. Wikipedia requests retry 429/5xx, timeouts and connection errors with backoff.
- `python -m scitech_pipelines clean [--input <snapshot>] [--out data/processed/documents]`: the arXiv snapshot to Parquet partitioned by `year=`, with PySpark in local mode (ADR 0005). Keeps `--category` (default `cs.CL`, ADR 0003), normalises the fields, drops records without abstract, title or first-version date, de-duplicates by `doc_id` (latest record wins), and writes `_clean_manifest.json` with every count (in, kept, dropped by reason, duplicates, out, per year). DuckDB recounts the category on the same file and a mismatch fails the run (`--skip-duckdb-check` to skip). A `--sample-size` (default 200) record sample for golden-set writing goes to `<out>-sample/`. Re-running replaces the output. Columns: `doc_id`, `source`, `title`, `abstract`, `authors`, `categories`, `published_at`, `updated_at`, `url`, `license` (`CC0-1.0`: the licence of title and abstract), `year`.
- `python -m scitech_pipelines validate [--input data/processed/documents] [--golden evaluation/golden_set/golden.jsonl]`: data quality checks on the whole cleaned dataset with DuckDB (no Java, runs on Windows): schema, `doc_id`/`title`/`abstract` present, `doc_id` unique and without version suffix, `published_at` between 1990 and today with `year` matching it, `updated_at` in range, every record in `--category`, fixed `source`/`license`/`url`, count equal to `_clean_manifest.json`, and with `--golden` (repeatable) that every `relevant_doc_ids` exists. Prints PASS/FAIL per check; exit code 1 if any fails.
- `python -m scitech_pipelines profile [--raw <snapshot>] [--documents data/processed/documents] [--wiki data/raw/wikipedia] [--out pipelines/reports/data_profile.md] [--clean-peak-mb <MB>]`: the data profile (W2-D3-FAO-1) with DuckDB (no Java, runs on Windows where the raw snapshot is). Reads the raw snapshot, the cleaned documents, both manifests and, if present, the raw Wikipedia pages, and writes the Markdown report plus the same numbers as `<out>.json`; every section says how its numbers were computed. Peak memory of `clean` is measured outside it (Kaggle cell with a process poller) and passed with `--clean-peak-mb`. Regenerate the report rather than editing it by hand.
- `clean` needs Java 17+ and does **not** run natively on Windows. Run it in WSL2, Colab, or a Kaggle **CPU** notebook (Accelerator: None, so no GPU quota is used) with the arXiv dataset added as input and `--input /kaggle/input/.../arxiv-metadata-oai-snapshot.json`. Spark settings: `--master`/`SPARK_MASTER` (default `local[*]`), `--driver-memory`/`SPARK_DRIVER_MEMORY` (default `4g`).
- Spark tests skip (not fail) without PySpark or without Java 17+ (an older Java, e.g. Java 8 on a Windows laptop, counts as none; `java -version` is checked), so `make test` works on Windows; CI runs them. They use one `local[1]` session on small JSON Lines files built from `tests/fixtures/sample.jsonl`.
- Tests never call Kaggle or Wikipedia: they use fakes (`tests/test_download.py`).
