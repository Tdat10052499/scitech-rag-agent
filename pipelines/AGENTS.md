# pipelines/ — data ingestion

Scope: download open datasets, clean them, split into chunks, create embeddings, load them into the vector store.
Source of truth for output: `docs/contracts/chunk.schema.json`. Sources and licences: `docs/03-data-sources.md`.

- Code in `src/scitech_pipelines/`, tests in `tests/`. Runtime dependencies in `requirements.txt` (create it with your first dependency).
- Every step must be re-runnable (idempotent) and take paths/URLs from arguments or env vars, not constants.
- Raw and processed data go to the git-ignored `data/` directory, never into git.
- Respect source terms and rate limits (e.g. pause between API requests). Record licence per record in the `license` field.
- Large-scale processing (Spark or similar) is justified only if the data volume requires it; record that decision in `docs/decisions/`.
- Validate outputs against the chunk schema in tests.

## Commands
- `python -m scitech_pipelines download --source arxiv|wikipedia|all [--out data/raw]`: raw data into `data/raw/<source>/` with a `manifest.json` (sizes, SHA-256). Re-running skips a complete source; `--force` downloads again. arXiv needs a Kaggle login (`kaggle auth login`); Wikipedia options: `--wiki-depth` (default 2), `--wiki-pause` (default 1 s), `--wiki-max-pages` (for a quick test). The arXiv manifest records the Kaggle dataset `version` (ADR 0003; W6 names the frozen index after it); the Wikipedia manifest records page counts per category depth, and pages without text are listed in `pages_without_text.txt` so a resumed run skips them. Wikipedia requests retry 429/5xx, timeouts and connection errors with backoff.
- `python -m scitech_pipelines clean [--input <snapshot>] [--out data/processed/documents]`: the arXiv snapshot to Parquet partitioned by `year=`, with PySpark in local mode (ADR 0005). Keeps `--category` (default `cs.CL`, ADR 0003), normalises the fields, drops records without abstract, title or first-version date, de-duplicates by `doc_id` (latest record wins), and writes `_clean_manifest.json` with every count (in, kept, dropped by reason, duplicates, out, per year). DuckDB recounts the category on the same file and a mismatch fails the run (`--skip-duckdb-check` to skip). A `--sample-size` (default 200) record sample for golden-set writing goes to `<out>-sample/`. Re-running replaces the output. Columns: `doc_id`, `source`, `title`, `abstract`, `authors`, `categories`, `published_at`, `updated_at`, `url`, `license` (`CC0-1.0`: the licence of title and abstract), `year`.
- `python -m scitech_pipelines validate [--input data/processed/documents] [--golden evaluation/golden_set/golden.jsonl]`: data quality checks on the whole cleaned dataset with DuckDB (no Java, runs on Windows): schema, `doc_id`/`title`/`abstract` present, `doc_id` unique and without version suffix, `published_at` between 1990 and today with `year` matching it, `updated_at` in range, every record in `--category`, fixed `source`/`license`/`url`, count equal to `_clean_manifest.json`, and with `--golden` (repeatable) that every `relevant_doc_ids` exists. Prints PASS/FAIL per check; exit code 1 if any fails.
- `python -m scitech_pipelines profile [--raw <snapshot>] [--documents data/processed/documents] [--wiki data/raw/wikipedia] [--out pipelines/reports/data_profile.md] [--clean-peak-mb <MB>]`: the data profile (W2-D3-FAO-1) with DuckDB (no Java, runs on Windows where the raw snapshot is). Reads the raw snapshot, the cleaned documents, both manifests and, if present, the raw Wikipedia pages, and writes the Markdown report plus the same numbers as `<out>.json`; every section says how its numbers were computed. Peak memory of `clean` is measured outside it (Kaggle cell with a process poller) and passed with `--clean-peak-mb`. Regenerate the report rather than editing it by hand.
- `python -m scitech_pipelines chunk [--input data/processed/documents] [--out data/processed/chunks] [--max-words 320] [--overlap-words 48]`: the cleaned documents to `chunks.parquet` with the fields of `docs/contracts/chunk.schema.json` (no `embedding_model` yet: `embed` sets it) and `_chunk_manifest.json` (counts, chunks per document, words per chunk). `text` is `<title>. <abstract window>`; an abstract that fits `--max-words` with its title is one chunk (`<doc_id>#0`), a longer one becomes windows overlapping by `--overlap-words`. Lengths are in words because the embedding model is chosen after this step (ADR 0007): set `CHUNK_MAX_WORDS`/`CHUNK_OVERLAP_WORDS` from the model's input limit and re-run (seconds, DuckDB, no Java). `published_at` is an ISO date string as in the schema. A re-run replaces only `chunks.parquet` and `_chunk_manifest.json`; an `--out` that holds other files is refused, so a typo cannot delete data. The environment variables are read only by `chunk`.
- `python -m scitech_pipelines embed --model <name> [--input data/processed/chunks] [--out data/processed/embeddings] [--batch-size 64] [--part-size 8192] [--passage-prefix ""] [--limit N] [--force]`: one vector per chunk with a sentence-transformers model (`--model` or `EMBEDDING_MODEL`, chosen in ADR 0007; never a name in the code), L2-normalised float32, written as `part-NNNNN.parquet` with `chunk_id`, `embedding` and `embedding_model`. Chunks are taken in `chunk_id` order; each finished part is written at once, so a re-run after a crash resumes at the first missing part, and a re-run of a complete output skips it. `_embed_state.json` keeps the settings: a re-run with another model, prefix, part size, limit or re-chunked input fails instead of mixing vectors (`--force` starts again). An `--out` that holds files of other steps is refused, with or without `--force`. `_embed_manifest.json` records counts, `chunks_per_second` and the GPU for ADR 0007. Needs `pip install -r pipelines/requirements-embed.txt` (sentence-transformers and PyTorch, not installed by CI) and a GPU notebook (Kaggle or Colab); tests use a fake encoder. `--limit` embeds only the first N chunks, for comparing models.
- `python -m scitech_pipelines load [--chunks data/processed/chunks] [--vectors data/processed/embeddings] [--out data/processed/index] [--collection NAME] [--batch-size 256] [--force]`: upserts every vector of a finished `embed` run with its chunk's fields as payload into Qdrant through DAT's store (`scitech_agent.store.QdrantStore`; `QDRANT_URL`, `QDRANT_COLLECTION`, `--collection` overrides), so `agent/src` must be on `PYTHONPATH` next to `pipelines/src`. Point ids are `uuid5(chunk_id)`, so a re-run replaces the same points. Finished parts are kept in `<out>/_load_state.json` and an interrupted run resumes at the next part; other settings (vectors, chunks, collection) need `--force`. At the end the collection must hold exactly one point per chunk; `<out>/_load_manifest.json` records counts, times and `index_snapshot` for evaluation runs. Tests use a fake store and a fake Qdrant over `httpx.MockTransport`; `tests/test_load_integration.py` (marked `integration`) loads the fixtures into a real Qdrant when one answers at `QDRANT_URL`.
- `python -m scitech_pipelines incremental-fetch --from YYYY-MM-DD [--until YYYY-MM-DD] [--set cs:cs:CL] [--category cs.CL] [--out <path>.jsonl] [--base-url https://oaipmh.arxiv.org/oai] [--pause 3]`: prototype for ADR 0008 (W3-D4-FAO-1). Harvests arXiv OAI-PMH `ListRecords` (`metadataPrefix=arXiv`) for a datestamp range (both days inclusive) and one set, following `resumptionToken`, with at least 3 s between requests (arXiv's limit; a smaller `--pause` is refused) and retries of 429/5xx (honouring `Retry-After`), timeouts and connection errors; `noRecordsMatch` means zero records. Records whose `categories` contain `--category` (`''` keeps all) are written as JSON Lines in the shape of the Kaggle snapshot, so `clean --input <that file> --out <a separate directory>` normalises them with the same code (`clean` replaces its `--out`, so never point it at the main documents). `<out stem>.manifest.json` records the settings and counts (harvested, deleted, not in category, kept, pages, requests). The default `--out` is `<data-dir>/raw/arxiv-oai/<set>_<from>_<until>.jsonl` (`:` becomes `-` for Windows). Runs on Windows (no Java); tests use a fake session.
- `python pipelines/scripts/index_profile.py --retriever dense --retriever bm25 --retriever hybrid [--filter <JSON>] [--collection NAME] [--size label=path] [--out <json>]`: W3-D5-FAO-1. Query latency (p50/p95 over 100 queries), a filter check with `retrieval.matches`, the Qdrant collection, its disk use and memory (through `docker`), and other index sizes; prints the tables of `pipelines/reports/index_profile.md`. A bare `dense`/`bm25`/`hybrid` is the agent's retriever from the environment (`retriever_from_env`); retrievers are measured one at a time.
- `python -m scitech_pipelines run-all [--limit N] [--snapshot <arXiv snapshot>] [--model ...] [--device ...] [--collection NAME] [--category cs.CL] [--golden <file>] [--from STEP] [--to STEP]`: W4-D2-FAO-1. Runs download -> (sample) -> clean -> validate -> chunk -> embed -> load, each as its own `python -m scitech_pipelines` process with the paths of `<data-dir>`, so `PYTHONPATH` must hold `pipelines/src` and `agent/src`. Each step's output is shown and copied to `<data-dir>/logs/run-all-<UTC time>/<nn>-<step>.log`; `run-all.json` there records the steps, exit codes and seconds. The run stops at the first failed step; `--from` / `--to` run part of the chain (for example `--to chunk` without a GPU, `--from embed` in a GPU notebook). `--snapshot` skips the download. `--limit N` keeps the first N records of the category (`sample` step) and puts everything after the download in `<data-dir>/limit-<N>/` and the collection `<collection>_limit_<N>`, so a small run never touches the full data or index; `validate` checks `--golden` only on a full run. The embedding model is checked before the first step. Tests fake the steps; `tee_step` is tested with a real `--help` process.
- `clean` needs Java 17+ and does **not** run natively on Windows. Run it in WSL2, Colab, or a Kaggle **CPU** notebook (Accelerator: None, so no GPU quota is used) with the arXiv dataset added as input and `--input /kaggle/input/.../arxiv-metadata-oai-snapshot.json`. Spark settings: `--master`/`SPARK_MASTER` (default `local[*]`), `--driver-memory`/`SPARK_DRIVER_MEMORY` (default `4g`).
- Spark tests skip (not fail) without PySpark or without Java 17+ (an older Java, e.g. Java 8 on a Windows laptop, counts as none; `java -version` is checked), so `make test` works on Windows; CI runs them. They use one `local[1]` session on small JSON Lines files built from `tests/fixtures/sample.jsonl`.
- Tests never call Kaggle or Wikipedia: they use fakes (`tests/test_download.py`).
